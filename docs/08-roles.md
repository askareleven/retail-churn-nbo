# 08 · Роли в проекте и глубина обучения

**Идея:** в реальной команде над таким проектом работают разные люди: ML Engineer, Data Scientist, Data Engineer, DevOps и другие. Ты учишься на **ML Engineer**. Поэтому для каждой роли задан режим: где ИИ учит, где объясняет суть, а где просто выдаёт готовые команды.

## Три режима

| Режим | Что делает ИИ | Что нужно от тебя |
|---|---|---|
| 🎓 **Учим** | Полный формат из `02`: «что и зачем», код малыми шагами, объяснение строк, проверочный вопрос | Объяснить своими словами (Definition of Done) |
| 🧩 **Суть** | Готовый код или команды + 3–5 строк «что это делает и где может сломаться». Без экзамена | Понимать картину в целом, уметь ответить на собеседовании «что здесь происходит» |
| 📋 **Рецепт** | Готовые команды по шагам, одна строка «что делает», как проверить результат, что делать при типичной ошибке. Без теории и вопросов | Выполнить и проверить результат. Если сломалось — прислать ошибку, ИИ починит |

## Роли и режимы

| Роль | Что делает в проекте | Режим |
|---|---|---|
| **ML Engineer** | Постановка ML-задачи, признаки, обучение, метрики, валидация по времени, эксперименты в MLflow, упаковка модели, контракт `/predict` | 🎓 |
| **Data Scientist / аналитик** | EDA, определение churn, статистика, интерпретация результатов | 🎓 (база аналитика у тебя есть, идём быстрее) |
| **QA (тесты)** | pytest на данные, функции, утечки и модель | 🎓 |
| **Data Engineer** | Скачивание данных, схемы ClickHouse, загрузка CSV | 📋 загрузка и Kaggle API, 🧩 DDL таблиц (ClickHouse ты знаешь); 🎓 только `MergeTree` и `ORDER BY` |
| **Backend** | FastAPI-эндпоинты, pydantic-схемы | 🧩 (понимать запрос и ответ, валидацию; код готовый) |
| **Frontend / BI** | Streamlit-дашборд | 🧩 (код готовый, твой фокус: выводы и подписи графиков) |
| **DevOps / Platform** | Docker, docker-compose, GitHub Actions, Kubernetes, облако, Terraform, мониторинг инфраструктуры, секреты | 📋 (Dockerfile и CI-файл: 🧩, понять, что в них написано) |
| **Product / бизнес** | Зачем нужна метрика, какой эффект для бизнеса | 🧩 (нужно для рассказа о проекте в портфолио) |

**Моя рекомендация по DevOps** (можешь не согласиться): Kubernetes, Terraform, облако и администрирование серверов остаются чистым 📋, их можно не учить. А Docker и GitHub Actions я поставил в 🧩: на собеседованиях ML Engineer почти всегда спрашивают, как упаковать модель в контейнер и как устроен CI. Достаточно понимать, что написано в Dockerfile и в CI-файле, учить глубоко не нужно.

## Как выбрать режим, если сомневаешься
- Решение влияет на **качество модели или метрики**: это ML Engineer, режим 🎓.
- Решение про то, **где и как это запускается**: это DevOps, режим 📋.
- Любую зону можно поменять командой: «объясни подробнее» повышает режим, «просто дай команды» понижает.
- Если в зоне 📋 сломалось: присылаешь текст ошибки, ИИ чинит и коротко говорит, в чём была причина. Урока не будет.

## Применение к задачам

| Задача | 🎓 Учим | 🧩 Суть | 📋 Рецепт |
|---|---|---|---|
| 1. Окружение | (готово) | | |
| 2. Данные в ClickHouse | зачем `MergeTree` и `ORDER BY`; проверка количества строк | DDL таблиц | Kaggle API, docker-compose с ClickHouse, загрузка CSV |
| 3. EDA | всё: распределения, сезонность, определение churn | | |
| 4. Признаки | всё: RFM, признаки по категориям, проверка на утечки | оптимизация SQL-витрины | |
| 5. Baseline и модель churn | всё: split по времени, метрики, LightGBM | | запуск сервера MLflow |
| 6. NBO | всё: кандидаты, ранжирование, MAP@12 | | |
| 7. API и Docker | pytest, логика предсказания, контракт ответа | FastAPI, pydantic | Dockerfile, запуск контейнера |
| 8. Дашборд, CI, портфолио | выводы и метрики для README, рассказ о проекте | Streamlit | GitHub Actions |

Для проектов 9–10 из `06` (MLOps, высоконагруженный inference) режимы пересмотрим после проекта 3, когда будет понятно, какая работа тебе ближе.
